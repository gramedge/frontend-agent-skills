# Prototype to Page

根据 Figma、产品原型图或页面截图，在现有项目中实现可运行、可维护的 Vue 页面。

## 开始前

先检查目标项目，而不是直接生成一套独立代码。确认：

- 项目说明文件和适用的 Agent 指令。
- Vue、TypeScript、构建工具和 Element Plus 的实际版本。
- 路由、状态管理、请求封装、样式体系和目录约定。
- 已有的页面布局、公共组件、图标、图片和设计变量。
- 项目提供的 lint、类型检查、测试、构建和预览命令。

如果项目技术栈或用户要求与本 Skill 不一致，以用户要求和项目现有约定为准。不要为了套用本 Skill 而迁移技术栈。

## 分析输入

从可用输入中识别：

- 页面整体区域及其层级关系，例如页头、侧栏、筛选区、内容区、表格和弹窗。
- 重复出现、适合复用的组件。
- 表单默认值、校验、按钮状态、分页、加载态、空状态和错误状态。
- 跳转、查询、提交、切换、展开和关闭等主要交互。
- 图片、图标、字体、颜色、间距和尺寸信息。
- 桌面端、移动端或响应式要求。

不要把原型中的静态内容误当成完整业务逻辑。接口、字段或交互不明确时，优先从项目现有实现中寻找依据；仍无法确定时，采用容易替换的最小实现，并在交付说明中列出假设。

## 实现原则

- 优先复用项目已有组件、布局、样式变量、类型和工具函数。
- 项目已经使用 Element Plus 时，优先使用其组件、交互行为和默认样式。
- 不要擅自引入新的 UI 组件库，也不要重复实现 Element Plus 已提供的基础组件。
- 默认使用 Vue 3、TypeScript 和 Composition API；遵循项目现有的单文件组件与代码风格。
- 优先还原页面结构、布局层级、模块关系、信息密度和主要交互。
- 除非用户明确要求，不追求像素级复刻，不为细微视觉差异堆叠复杂 CSS。
- 图片和图标优先使用设计稿提供的资源或项目已有资源。不要用表情符号代替正式图标。
- 避免不必要的绝对定位、固定高度和逐像素偏移。使用与页面结构相符的 Flex、Grid 或项目既有布局方案。
- 将只在当前页面使用的代码留在页面附近；只有存在真实复用需求时才提取公共组件。
- 保持改动范围聚焦。不要顺带重构无关模块、替换依赖或改变全局样式。
- 不要编造可工作的后端接口。缺少接口时，沿用项目已有 mock 方式，或把临时数据隔离并明确标注。

## 实施流程

1. 找到目标路由、相邻页面和可复用组件，确定实现位置。
2. 将原型拆成页面区域和组件，明确数据流与交互边界。
3. 先完成整体结构和主要布局，再实现控件、状态和细节样式。
4. 接入项目已有的路由、状态、请求和权限机制；只实现需求范围内的行为。
5. 使用设计稿资源，并为缺失、加载失败或内容溢出保留合理表现。
6. 检查常见尺寸下的换行、滚动、遮挡、表格宽度和弹层位置。
7. 运行项目已有的格式化、lint、类型检查、测试或构建命令。不要为了通过检查而关闭规则。
8. 有可用预览环境时，实际打开页面检查布局、交互和控制台错误，并修复确认到的问题。

## 完成标准

交付前确认：

- 页面能通过项目现有入口访问，且没有明显运行时错误。
- 页面结构和核心模块与输入一致。
- 主要操作具有合理反馈，表单、加载、空数据和错误状态按需求或项目惯例处理。
- 没有无必要的新依赖、重复组件或全局样式污染。
- 类型检查、lint、测试或构建结果已记录；无法运行的检查说明原因。
- 最终说明包含修改内容、验证结果、重要假设，以及仍需用户提供的接口或设计信息。
